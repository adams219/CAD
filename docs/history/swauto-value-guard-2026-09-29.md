# SWAUTO 치수 값 보존 수정 - 2026-09-29

SWAUTO(`src/tools/gstarcad-dimstyle/gstarcad_dimstyle_keep_tolerance.lsp`)가 SolidWorks 치수를 AM_ISO 스타일로 바꿀 때 화면에 보이는 치수 숫자와 공차가 바뀌는 문제를 고쳤다. 모듈 버전은 `260929-value-guard-3`다.

## 발견 경위

- 2026-07-13 통합 테스트에서 SWAUTO 실행 뒤 치수 143개 중 73개의 값 기록이 달라져 통합 앱이 되돌렸다. 30장 도면에서는 254개 중 154개였다. 확인된 예는 핸들 `37C1`(`DIMLFAC` 0.5→1, 공차 0/0→0.1/0.1)이다.
- 이 되돌림은 통합 앱(`SWCADRUN`) 안에만 있었다. 사용자가 평소 단독으로 쓰는 `SWAUTO`에는 없었다.
- 2026-09-29 복사본 17장 테스트에서 아래 문제를 추가로 확인했다.

## 원인과 수정

### 1. 공차 없는 치수의 `DIMLFAC` 손실

`swdt-process-dimension`(1단계 스타일 변경)은 공차가 켜진 치수만 DSTYLE override를 새 스타일로 옮기고, 공차가 없는 치수는 override를 모두 지웠다. 그래서 상세도처럼 `DIMLFAC`가 1이 아닌 치수는 대상 스타일의 1로 돌아가 숫자가 두 배로 보였다. 숨은 공차값(`DIMTP`/`DIMTM`)도 대상 스타일 기본값(0.1)으로 바뀌었다.

수정: 공차 없는 치수도 대상 스타일과 다른 `DIMLFAC`, `DIMTOL`, `DIMLIM`, `DIMTP`, `DIMTM`을 override로 유지한다.

### 2. 소수 자리 변경

스타일을 바꾸면 소수 자리(`DIMDEC`)도 대상 스타일 값으로 바뀌었다. 예: `29.406`→`29.41`(3자리→2자리), `0.5`→`0.48`(1자리→2자리).

수정: `DIMDEC`, `DIMRND`, `DIMADEC`를 유지한다. 맞춤공차 변환(3단계)의 DSTYLE에도 넣었다. 0 생략(`DIMZIN`)은 일부러 대상 스타일을 따른다. SolidWorks가 내보내는 `DIMZIN 12`를 그대로 쓰면 `0.5`가 `.5`로 표시된다.

### 3. 맞춤공차 아래 공차 부호

`swdt-mech-fit-tolstack`이 아래 공차를 항상 `-`로 붙였다. `DIMTM`은 기준보다 아래로 가는 양이라 화면 값은 `-DIMTM`이다. 그래서 위아래 부호가 같은 끼워맞춤(D10, F7, G7, f7, g6, k6, m6, p6 등)이 틀리게 표시됐다. 예: `4 D10`(`+0.078 / +0.030`)이 `+0.078 / -0.03`으로 표시됐다. 옛 SWAUTO에도 있던 문제다.

수정: 두 공차가 모두 0이 아니면 `+DIMTP`와 `-DIMTM`의 부호를 그대로 쓴다. 한쪽이 0인 H/h 형식 출력은 바꾸지 않았다.

### 4. 축척 뷰 맞춤공차의 기준 치수 절반

실측 결과 GstarCAD의 `Measurement` 속성과 DXF 42는 이미 `DIMLFAC`가 곱해진 값이다(2:1 뷰에서 기하 길이 8, 측정값 4). `swdt-dim-measurement`는 여기에 `DIMLFAC`를 한 번 더 곱해서, 2:1 뷰의 `Ø4 D10`이 Mechanical 맞춤공차 기준 치수 2로 저장됐다. 기준 치수가 틀리면 공차표 조회 구간이 달라질 수 있다.

수정: `Measurement`나 DXF 42가 있으면 그대로 쓰고, 정의점 거리로 대신 계산할 때만 `DIMLFAC`를 곱한다.

### 5. 맞춤공차 변환 때 구멍 설명 글자 삭제

`3-<>H7 Hole DP3` 같은 치수 글자가 맞춤공차 변환 뒤 `<>` + 맞춤 기호만 남아서, 개수 `3-`와 깊이 `Hole DP3`가 사라졌다.

수정: `<>` 앞의 글자와 맞춤 기호 뒤의 글자를 유지한다. 뒤 글자에 `+`, `/`, `±`가 있으면 공차가 두 번 보일 수 있어 넣지 않는다.

### 6. SolidWorks 지름(중심선 거리 x2) 표시

SolidWorks는 중심선까지의 거리를 두 배로 해서 지름으로 보여 주는 치수가 있다(거리 34를 `Ø68`로 표시). DWG에는 이 배율이 없어서, SWAUTO가 치수를 수정해 GstarCAD가 다시 그리면 `Ø34`가 된다. 기존 값 비교(측정값, `DIMLFAC` 등)로는 잡히지 않는다.

수정: 치수 블록에 실제로 그려진 첫 숫자를 실행 전후로 비교한다(`swdt-shown-guard`). 전후 숫자가 정확히 2배 관계이고 치수 글자가 측정값뿐인 치수(`<>`, `%%c<>`)는 `DIMLFAC`를 2배로 넣어 원래 숫자를 되살린다. 그 밖에 숫자가 달라진 치수는 되돌리지 않고 `CHECK NEEDED`로 알린다.

한계: 통합 워크플로(`SWCADRUN`)는 자체 전후 비교에서 `DIMLFAC` 변화를 원래 값으로 되돌리므로, 워크플로 안에서는 이 보정이 아직 유지되지 않는다.

### 7. 작은 수정

- `swdt-trim-tol-real`: `DIMZIN`이 뒤쪽 0을 이미 지운 경우 `10`이 `1`로 잘리던 문제를 고쳤다.

## SWAUTO 안의 전후 비교

`swdt-run-autofix-core`가 1단계 전에 치수마다 값을 기록하고 4단계 뒤 비교한다.

- 비교 값: 측정값, `DIMLFAC`, `DIMTP`, `DIMTM`, `DIMTOL`, `DIMLIM`, `DIMDEC`, `DIMRND`, `DIMADEC`
- 달라진 일반 치수는 기록해 둔 값으로 되돌리고 다시 비교한다.
- 맞춤공차로 변환된 치수의 `DIMTOL`/`DIMLIM` 변화는 기존 SWAUTO 동작으로 보고 되돌리지 않는다.
- 맞춤공차 치수의 다른 값이 바뀌었거나 치수가 사라지면 되돌리지 않고 `SWAUTO RESULT: CHECK NEEDED`로 멈춘다.
- SolidWorks에서 막 가져온 치수는 GstarCAD 측정값이 `-1`이다. 이 경우 측정값은 비교하지 않는다.
- 마지막으로 치수 블록에 그려진 첫 숫자를 비교한다(위 6번).

## 테스트

- 도구: `diagnostics/gstarcad-dimstyle/run_swauto_value_test.ps1`, `swauto_value_probe.lsp`, `analyze_swauto_value_test.ps1`
- 원본 DWG는 읽기만 하고 해시로 확인한다. 모든 CAD 작업은 `tmp\` 복사본에서만 한다.
- 비교 기준은 치수 블록 안에 실제로 그려진 글자다. SWAUTO의 자체 보고와 독립적이다.

## 남은 차이와 결정

- 구멍 설명의 탭 드릴 지름: SolidWorks는 `8 x Ø3 ... M4-6H`처럼 정수로 반올림해 보여 주지만 실제 치수값은 3.3이다. SWAUTO 후에는 옛 버전과 새 버전 모두 `Ø3.3`으로 보인다. 사용자 결정(2026-09-29): 실제 값 표시를 유지한다.
- 통합 워크플로(`SWCADRUN`)는 자체 전후 비교에서 `DIMLFAC` 변화를 되돌리므로, 중심선 거리 x2 지름 보정은 워크플로 안에서 아직 유지되지 않는다. 워크플로 전체 흐름은 이번에 다시 실행하지 않았다.
- 옛 SWAUTO로 이미 처리한 도면에는 위 문제들이 남아 있을 수 있다. 같은 테스트 도구로 해당 원본 DWG에 `-Modes old`를 실행하면 옛 SWAUTO가 바꾼 치수 목록을 얻을 수 있다.
