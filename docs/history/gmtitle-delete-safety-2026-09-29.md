# GMTITLE 삭제 안전장치 - 2026-09-29

GMTITLE 변환(`src/tools/gmtitle/swcad_title_scale.lsp`)이 옛 표제란과 도면틀을 정리할 때 지우는 범위와 삭제 동작을 고쳤다. GMTITLE 검토의 2단계이고, 모듈 버전은 `260929-delete-safety-1`이다. 1단계(표제란 값)는 `docs/history/gmtitle-title-values-2026-09-29.md`에 있다.

## 원인과 수정

### 1. 표제란에 닿기만 한 선·해치 삭제

`swcad-title-source-title-graphic-handles`는 도면 전체(배치 공간 포함)의 선·폴리선·해치·솔리드 가운데, 경계 상자가 옛 표제란 상자(+1 mm)에 닿기만 해도 지웠다. 표제란까지 이어진 중심선, 모서리를 덮는 단면 해치, 표제란 위에 선 부품표 선도 함께 지워질 수 있었다.

30장 fixture에서 이 목록은 다음과 같았다.

- 표제란 안에 완전히 들어 있는 것: 선 1080개, 해치 169개. 모두 SolidWorks 표제란 표의 선이다.
- 표제란에 닿기만 하는 것: 해치 13개. 모두 도면틀 오른쪽 아래 모서리의 10×10 mm 사각형(SolidWorks 양식 모서리 표시, `FRAME050` 레이어)이다.

수정 후 지우는 것은 다음 둘뿐이다.

- 옛 표제란 상자(+1 mm) 안에 완전히 들어 있는 것
- 표제란에 닿기만 하되, 도면틀 테두리 여백(도면틀 안, 가장자리에서 11 mm 이내)에 완전히 들어 있는 것

도면 쪽으로 뻗은 것은 표제란에 닿아도 남긴다. 30장 fixture에서는 지우는 목록이 수정 전과 같다(시트 30장, 차이 0개).

### 2. 두 번 지우면 되살아남

`swcad-title-delete-ename`은 이미 지운 객체인지 확인하지 않고 `entdel`을 불렀다. GstarCAD에서 지운 객체에 `entdel`을 한 번 더 하면 객체가 되살아난다(테스트로 확인). 같은 객체가 두 정리 목록에 들어가면, 변환 뒤 다시 나타났다.

수정: 지운 객체는 다시 건드리지 않는다. 반환값은 세 가지다.

| 반환값 | 뜻 |
| --- | --- |
| `T` | 이번에 지웠다 |
| `ALREADY` | 이미 지워져 있었다 |
| `nil` | 아직 남아 있다(지우지 못함) |

삭제 개수는 이번에 지운 것만 센다.

### 3. 삭제 실패를 성공으로 기록

옛 표제란이나 도면틀이 잠긴 레이어에 있으면 삭제에 실패해도 로그에는 "삭제: 예"로 남았다. 옛 표제란이 새 GMTITLE 밑에 그대로 남는다.

수정:

- GMTITLE을 만들기 전에 옛 표제란 INSERT, 도면틀 INSERT, 표제란 글자가 잠긴 레이어에 있는지 확인한다. 하나라도 있으면 `ABORT_SOURCE_ON_LOCKED_LAYER`로 멈추고 도면은 바꾸지 않는다.
- 변환 뒤 옛 표제란·도면틀·글자가 실제로 사라졌는지 다시 확인한다. 남아 있으면 성공 대신 `REVIEW_OLD_TITLE_NOT_DELETED`로 멈춘다. 이 상태에서는 SWCADRUN도 멈춘다. 적용 경로는 새 GMTITLE 값 옮기기, 기존 쌍 채택, 복제 마무리, 복제 쌍의 native 교체, MANUAL 마무리다.

### 4. 배치 공간 객체

표제란 선·해치, 도면틀 선, 시트 잔여물, 표제란 글자를 찾을 때 공간 구분이 없었다. 배치(layout) 공간에서 같은 좌표에 있는 객체도 대상이 될 수 있었다.

수정: 원본 표제란(없으면 원본 도면틀)이 있는 공간에서만 찾는다. 둘 다 없으면 모델 공간에서 찾는다.

## 테스트

단위 검사 18개를 30장 fixture 복사본에서 실행했고 모두 통과했다(`tmp/gmtitle-attr-test/step2_unit_probe.lsp`).

- `entdel` 두 번이 객체를 되살리는 것을 확인했다. 새 삭제에서는 되살아나지 않고, 두 목록에 있어도 한 번만 센다.
- 잠긴 레이어의 선은 지워지지 않고 "잠김", "남음"으로 보고된다.
- 표제란 규칙:
  - 표제란 안의 선과 테두리 여백의 모서리 면은 지운다.
  - 표제란을 넘어 도면으로 뻗은 선, 표제란 모서리를 덮고 도면으로 뻗은 면, 배치 공간의 선은 남긴다.
  - 배치 공간의 글자는 표제란 글자로 보지 않는다.
- 실제 30장: 새 규칙과 수정 전 규칙이 지우는 선·해치가 같다(차이 0개).

30장 워크플로 전체 테스트(`diagnostics/gmtitle-values/run_title_value_test.ps1 -EndToEnd -FullWorkflow`)도 실행했다.

- `SWCADRUN` 4회로 `COMPLETE`, `SWCADVERIFY` 검사 `SWCADVERIFY_FINAL_OK`
- 제목블록 값: 330칸 모두 계획과 같음
- 지워진 모델 공간 객체를 변환 전 도면과 비교했다. 1단계 코드 1693개, 2단계 코드 1693개였고 한쪽만 지운 객체는 0개다. 내역은 선 1215, 표제란 글자 223, 해치 195, 옛 표제란·도면틀 INSERT 60이다.
- 최종 실행: `tmp/gmtitle-value-test/260929_step2_final/summary.txt`, `RESULT: OK`. 이 실행에는 삭제 안전장치 단위 검사 18개가 포함된다. 모듈 SHA-256 `FB39B48C33D79AF6D7ED698024B0B83D7FA18199125981A659417C4711A471F4`는 `diagnostics/swcad-workflow/module-baseline.sha256`와 같다.

## 남은 것

- 시트 잔여물 정리는 바꾸지 않았다. 도면틀 크기에 비례하는 영역을 쓰기 때문에 다음 문제가 남는다.
  - 왼쪽 아래 8%×8% 영역의 선·호·원·해치를 지운다. A2에서는 약 47×34 mm까지 도면 영역에 들어간다.
  - 오른쪽 위 영역의 긴 `SW_NOTE` 블록도 지운다.
  - 영역이 옆 시트까지 닿는다. 30장 fixture에서는 옆 시트의 모서리 표시선만 걸렸다.
- 새 표제란에 칸이 없는 원본 글자(`Item ref` 등)는 지금처럼 옛 표제란과 함께 지우고 내용만 기록한다.
- 3단계(도중 오류 때 SWCADRUN이 멈추지 않는 경로)와 4단계(작업본 이름 날짜, 블록 이름 용지 판단, XREF 상태 안내)는 아직 하지 않았다.
